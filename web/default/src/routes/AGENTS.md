# Routes — TanStack File Routing Conventions

## OVERVIEW

Route definitions for web/default (React 19, TanStack Router). Route files are thin: perform guards, validation, and redirects in `beforeLoad`, then hand off UI to `@/features/...`.

## STRUCTURE

```
__root.tsx                  → root layout (setup check, theme, notFoundComponent, errorComponent)
(auth)/                     → route group (no path prefix): sign-in, etc.
(errors)/                   → route group: 401, 403, 404, 500, 503
_authenticated/             → layout route: session verification gate, AuthenticatedLayout
  dashboard/, chat/, etc.   → authenticated feature routes
  system-settings/          → admin-only with sub-sections via feature registries
index.tsx, about/, etc.     → public pages (no auth required)
```

## WHERE TO LOOK

- Authentication: `_authenticated/route.tsx` beforeLoad guards + `/sign-in` redirect logic
- Admin guard: `_authenticated/system-settings/route.tsx` ROLE.SUPER_ADMIN check
- Section handoff: `$section.tsx` with `*_SECTION_IDS` / `*_DEFAULT_SECTION` from `section-registry.tsx`
- Search validation: `createFileRoute` with `validateSearch: zodSchema`

## CONVENTIONS

1. **Thin routes** — beforeLoad does guards/validation/redirects; component renders one `@/features/...` entry
2. **beforeLoad** — use for setup check (__root.tsx), session verify (_authenticated), auth redirect ((auth)/), admin role check (system-settings)
3. **Search params** — validate with Zod schema via validateSearch; pass typed search to beforeLoad
4. **Dynamic params** — validate against feature registry IDs (e.g., AUTH_SECTION_IDS); redirect to default if invalid
5. **Redirects** — use `throw redirect({ to: '...', search: {...} })` pattern; preserve redirect intent with search params
6. **Layout nesting** — `_authenticated` wraps child routes; `_authenticated/system-settings` adds admin sub-layout; children render via `<Outlet />`
7. **routeTree.gen.ts** — auto-generated by TanStack Router; NEVER edit manually

## ANTI-PATTERNS

- Route files containing complex UI logic — move to `@/features/...`
- Inline hardcoded section IDs — use feature registry constants
- Skipping beforeLoad guards on protected routes
- Direct window.location navigation — use TanStack Router `Link` / `useNavigate`
- Modifying routeTree.gen.ts — it is regenerated on each build
